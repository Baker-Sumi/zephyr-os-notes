# 初期化

## 対象範囲

アーキテクチャ固有の準備後、Zephyrカーネルが初期化項目を実行し、アプリケーションの`main()`を呼び出すまでを扱います。

## 全体像

```mermaid
flowchart TD
    PREP[arch/*/prep_c.c] --> CSTART[z_cstart()]
    CSTART --> EARLY[EARLY]
    EARLY --> PRE1[PRE_KERNEL_1]
    PRE1 --> PRE2[PRE_KERNEL_2]
    PRE2 --> BG[bg_thread_main()]
    BG --> POST[POST_KERNEL]
    POST --> APP[APPLICATION]
    APP --> MAIN[main()]
```

## ディレクトリとファイル

| パス | 役割 |
| --- | --- |
| `arch/*/core/prep_c.c` | アーキテクチャごとのC実行環境準備を行い、`z_cstart()`へ到達する。 |
| `kernel/init.c` | 初期化レベルを走査し、カーネルのバックグラウンド処理と`main()`への移行を実装する。 |
| `include/zephyr/init.h` | `SYS_INIT()`と初期化レベルを定義する。 |

## 処理の流れ

1. アーキテクチャの準備コードが、Cコードの実行条件を整えて`z_cstart()`を呼びます。
2. [`z_cstart()`](https://github.com/zephyrproject-rtos/zephyr/blob/v4.4.2/kernel/init.c#L538-L580)は`EARLY`、`PRE_KERNEL_1`、`PRE_KERNEL_2`を順に実行します。
3. `z_sys_init_run_level()`は、リンク時に各レベルへ集められた`init_entry`を走査します。デバイス項目ならデバイス初期化、それ以外なら登録関数を呼びます。
4. バックグラウンドスレッドの[`bg_thread_main()`](https://github.com/zephyrproject-rtos/zephyr/blob/v4.4.2/kernel/init.c#L279-L361)が`POST_KERNEL`、`APPLICATION`、必要なら`SMP`を実行し、その後に`main()`を呼びます。

## 設定との対応

`SYS_INIT(init_fn, level, prio)`は、関数と初期化レベル・優先度を登録するマクロです。利用可能なレベルは[`include/zephyr/init.h`](https://github.com/zephyrproject-rtos/zephyr/blob/v4.4.2/include/zephyr/init.h#L136-L169)で確認します。デバイスドライバは通常、`DEVICE_DT_DEFINE()`などを通じて同じ初期化枠へ登録されます。

## 確認方法

```sh
git grep -n 'z_cstart' -- kernel arch
git grep -n 'SYS_INIT(' -- kernel drivers subsys
```
