# Cの最小基礎

## 対象範囲

Zephyrのソースを読む前に必要な、変数、関数、構造体（structure）、ポインタ（pointer）、`const`の最小限を扱います。C言語の網羅的な文法、動的メモリ確保、C++、CPU固有の仕組みは扱いません。

## 前提知識

PythonまたはRustで、変数、関数、if文を使ったことがあれば十分です。このページの例は通常のCであり、Zephyrを導入しなくても読み進められます。

## 全体像

CでZephyrを読むときに最初に困りやすいのは、`struct`と`*`です。次のように考えます。

> **ヒント: 実世界のたとえ**
>
> `struct`は、名前の付いた仕切りを持つ**工具箱**です。`struct device`なら、deviceに関する情報を一つにまとめた工具箱です。<br>
> ポインタは、工具箱そのものではなく「その工具箱は棚のこの場所にある」と書いた**住所メモ**です。`*`は住所メモを扱う印、`&`は工具箱の住所を調べる印、`->`は住所メモを頼りに工具箱の中を開く印です。

```mermaid
flowchart LR
    BOX["struct: 情報をまとめた工具箱"] --> ADDRESS["pointer: 工具箱の住所メモ"]
    ADDRESS --> ACCESS["->: 住所から中身へアクセス"]
```

## 処理の流れ

1. **構造体は関連する値を一箱にまとめます。**

   ```c
   #include <stdbool.h>

   struct led {
       int pin;
       bool is_on;
   };

   struct led board_led = {
       .pin = 13,
       .is_on = false,
   };
   ```

   `board_led`は`pin`と`is_on`を持つ一つの値です。`board_led.pin`のように`.`で箱の中身へアクセスします。

2. **ポインタは、その箱の住所を持ちます。**

   ```c
   struct led *led_address = &board_led;

   led_address->is_on = true;
   ```

   `&board_led`は`board_led`の住所です。`led_address`はその住所を保持します。`led_address->is_on`は、`(*led_address).is_on`と同じ意味で、「住所が指す箱の`is_on`」を表します。

3. **値渡しとポインタ渡しで、変更が届く範囲が違います。**

   ```c
   void turn_on_copy(struct led value)
   {
       value.is_on = true;   /* コピーだけを変更する */
   }

   void turn_on_original(struct led *address)
   {
       address->is_on = true; /* 元のboard_ledを変更する */
   }

   turn_on_copy(board_led);
   turn_on_original(&board_led);
   ```

   最初の呼出後も`board_led.is_on`は変わりません。二つ目は`board_led`の住所を渡しているため、元の値が変わります。Zephyrの`const struct device *dev`も、device全体を渡すのではなく、既存deviceの住所を渡す形です。

4. **`const`は「この経路からは変更しない」という約束です。**

   ```c
   void show_led(const struct led *address)
   {
       /* address->is_on = true; */ /* compile error */
       bool current = address->is_on;
   }
   ```

   `const struct led *`は、関数が読むだけで変更しないことを表します。これは「objectが絶対に変化しない」という意味ではありません。別の変更可能なポインタを持つコードがあれば、同じobjectを変更できます。

5. **ポインタを使う前に、住所が有効かを確認します。**

   ```c
   #include <stddef.h>

   void turn_on_if_present(struct led *address)
   {
       if (address == NULL) {
           return;
       }

       address->is_on = true;
   }
   ```

   `NULL`は「どのobjectも指していない」を表す特別な値です。`NULL`に`->`を使うと不正なアクセスになります。Zephyrでは`device_is_ready()`も、deviceが初期化に成功して使用可能かを確認するために使います。

> **注意: ポインタはRustの参照ほど安全ではない**
>
> Cのポインタには、所有者、寿命、排他が型として記録されません。`NULL`ではないことだけでなく、指すobjectがまだ存在すること、同時に変更してよいことも呼出側が守ります。

## 設定との対応

このページの例自体はKconfigやDevicetreeに依存しません。Zephyrでは、次のように基本Cの形と設定が結び付きます。

| Cの形 | Zephyrでの入力 | 確認する出力 |
| --- | --- | --- |
| `const struct device *` | Devicetree nodeとdriverの有効化 | `zephyr.dts`、`.config`、`struct device` |
| `struct gpio_dt_spec` | `gpios` property | generated Devicetree macro |
| `->api`の関数ポインタ | driver sourceとKconfig | `.config`、driver API表 |

## 確認方法

次のページへ進む前に、上の例について説明できるか確認します。

1. `board_led.pin`と`led_address->pin`が、どちらも同じ`pin`を読む理由。
2. `turn_on_copy()`では元の`board_led`が変わらず、`turn_on_original()`では変わる理由。
3. `const struct led *`から`is_on`へ代入できない理由。
4. `NULL`を確認してから`->`を使う理由。

答えを説明できたら、[ポインタと構造体からZephyrを読む](01-ポインタと構造体.md)で実際のZephyr型とdriver APIへ進みます。
