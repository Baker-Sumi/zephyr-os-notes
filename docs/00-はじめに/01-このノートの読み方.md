# このノートの読み方

## 対象範囲

このノートは、組込み開発者がZephyrの導入後にできるworkspaceと生成物から、ソースコードの関係を追うためのものです。導入コマンドとSDKは、内部構造を観察できる環境を再現するために扱います。OS別の導入障害の切り分けや、特定ボードだけに通用する書き込み手順は扱いません。

## 読むときの規則

- コードへのリンクはすべて`v4.4.2`タグに固定する。
- **設定時**（Kconfig、Devicetree）、**ビルド時**（CMake、生成物）、**実行時**（初期化、API）の記述を区別する。
- パスはZephyrリポジトリのルートから記す。例: `kernel/init.c`。
- `CONFIG_`で始まる名前はKconfigシンボル、`DT_`で始まる名前はDevicetree由来のCマクロである。
- `<workspace>`は`.west/`を含むwest workspace、`<app>`はアプリケーションのルートを指す。両者の関係は[ワークスペースの構造](../02-開発環境/03-ワークスペースの構造.md)で確認する。

## ローカルでの確認方法

```sh
west init --mr v4.4.2 <workspace>
cd <workspace>
west update
cd zephyr
git describe --exact-match --tags HEAD
git grep -n 'z_cstart'
```

`west init`の詳細は[導入手順と確認](../02-開発環境/02-導入手順と確認.md)を参照する。最後の二つのコマンドが`v4.4.2`のソースを対象としていることを確認してから記事を読む。
